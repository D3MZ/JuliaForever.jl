# Terminal

The `jf` command accepts a prompt in its arguments. With no prompt, TTY stdin and stderr and a `TERM` other than empty or `dumb` enable Julia's line editor. Enter sends a message; Ctrl+J inserts a newline. The editor also recognizes Shift+Enter when a terminal already sends `CSI 13;2u` or `CSI 27;2;13~`; `jf` does not enable extended keyboard protocols and terminals may send plain Enter instead. Arrow keys edit the input. Up and Down move between lines, then browse earlier or newer submitted prompts at the input boundaries. Drafts are restored when moving back down. Bracketed paste is inserted as one input, with CRLF or CR normalized to LF; spaces and tabs in the pasted text are retained. Ctrl+C clears the current input, and Ctrl+D exits if the input is empty or deletes forward otherwise. `/exit` ends the session.

Prompt history is held in memory for the current process only, separately from `--history` conversation storage. It can contain sensitive prompt text. The editor uses stderr; stdout may be redirected. If stdin is not a TTY, stderr is not a TTY, or `TERM` is unset or `dumb`, `jf` uses line-oriented input instead. Piped input sends one message per line and displays no banner or prompt. A TTY with the editor disabled still displays the banner and prompt on stderr. The same agent and conversation are retained across messages in one process.

Use `--provider` to select `openai`, `openai-responses`, `openrouter`, `anthropic`, or `google`. The flag overrides `JF_PROVIDER`, whose default is `openai`. `--model MODEL_ID` overrides the selected provider's model environment variable. IDs are passed literally; no catalog or fuzzy matching is performed. If either option is repeated, the last value wins. Set the selected provider's API key. Place options before the prompt. `--login-openrouter` and `--login-openrouter-callback` select OpenRouter and accept `--model` in any option order; if `--provider` is present with either login option, it must be `openrouter`.

The CLI saves a new SQLite session automatically when its first turn starts. Use `jf --continue` (or `-c`) to open the most recently modified session for the current working directory; if none exists, it starts a new session. Use `jf --resume` (or `-r`) to choose a project session from a numbered list, or `jf --session PATH|ID` to open an existing session by path or unique ID fragment. During a conversation, `/resume` opens the selector and switches sessions. Enter `q` or an empty line to cancel. `jf --no-session` starts in memory; a session selected with `/resume` is saved. The selector is line-oriented and does not yet support Pi's search, rename, delete, sorting controls, or cross-project browsing.

If `/resume` rejects a selection or encounters an expected filesystem error while opening it, the current session remains active. A current session with a fault or unprocessed queued inputs cannot be switched away from; `/tree` also blocks a branch change in that state. Malformed sessions appear as “Unavailable session” in the selector, and selecting one reports the history error. Other exceptions propagate.

Resume from the original project directory and select the required plugins and tool options again. The saved system context, including its working directory, instructions, and tool descriptions, is not regenerated; built-in tools operate in the current working directory, and current flags determine the plugins and tools available. Both `--session PATH` and `--history PATH` can open a history from another project, so resuming from a different directory can cause tools to modify the wrong project. Existing histories do not store a reliable structured original directory, and the CLI cannot detect this mismatch.

Use `--plugin PACKAGE` to load an explicitly selected native Julia plugin, and `--plugin-env PATH` to add a Julia environment containing it. Both options may be repeated before the prompt. The package must already be available and runs with your permissions. See [extensions](extensions.md) for the package interface, hook diagnostics, and limitations.

Sessions are stored under `~/.julia/juliaforever/sessions` by default. Set `JF_SESSION_DIR` or pass `--session-dir DIR` to use another directory; the flag takes precedence. Automatic discovery uses directory-based filenames to scope selections to the current working directory; explicit paths bypass that scoping. The CLI creates a session file only when a turn starts, with owner-only file permissions. Paths and IDs refer to Julia Forever's SQLite histories, not Pi's JSONL files. Session naming and forking are not yet connected to the CLI.

Enter `/tree` between turns to list the session's user messages and completed assistant responses, including other branches. Selecting a user message offers it for editing; submitting it starts a new branch. An empty edit keeps the original text, and `/cancel` aborts. Selecting an assistant response moves to that point and waits for the next message. `q` cancels the selector. Other branches remain in the history. A selection takes effect in the current process; reopening selects the last appended branch, as in Pi. The selector is line-oriented and does not yet support Pi's full tree UI, branch summaries, or selecting intermediate tool entries. Naming and forking are also not implemented.

`jf --history session.sqlite 'first prompt'`, followed by `jf --history session.sqlite 'next prompt'`, continues to record and resume an explicitly chosen file. The file holds one history; a standalone history is not added to automatic session discovery. SQLite.jl is installed with JuliaForever. Initial project instructions are retained in the history; resuming uses the current provider, tool configuration, and working directory. Session files can contain conversation text, instructions, tool calls and results, so protect them as you would the conversation. Place options before the prompt.

If a prior turn has a pending effect or is incomplete, the CLI exits with a diagnostic and the history file path before requesting the provider or running a tool. It never automatically retries the effect. Run `jf --history PATH --inspect-history` to display the recorded pending effects and tool arguments, and inspect external state before deciding what happened. Then record an explicit decision with `jf --history PATH --abandon 'inspected external state'`. Neither command requires provider configuration or dispatches a request or tool. Abandoning records the reason but does not undo an effect. Reopen the session to start a new turn.

If a restored history still has queued steering or follow-up messages, the CLI reports them and refuses a new prompt. A `/resume` or `/tree` selection with queued messages is refused and leaves the current session unchanged. Saved messages remain in the history; messages in an ephemeral session exist only in memory. Start a new session to resubmit messages after reviewing them.

The inspection output can contain sensitive tool arguments. Abandonments recorded by older versions as `Interrupt` events can lack matching tool replies, which strict providers may reject. See [history storage](history.md) for database and platform limitations. Concurrent changes may cause a revision rejection; reopen and inspect before proceeding.

Assistant text is written and flushed as it arrives on stdout, with a newline after each assistant message when needed. Tool starts and outcomes go to stderr; successful tool output and tool arguments are not displayed. For valid text, tool errors and session diagnostics redact the configured provider key in raw text and standard single-layer Julia `repr` strings; other encodings and repeated escaping are not decoded. Incomplete responses are reported without the provider's raw error payload. Raw provider events and HTTP response bodies are not intentionally logged; recognized HTTP and malformed JSON failures omit their details. Assistant text is output as received and is not filtered. The `--login-openrouter` flow writes its authorization URL and code prompt to stdout; `--login-openrouter-callback` writes an authorization URL and waits for a local browser callback.

The command returns 0 after a completed response, including one that recovered from a tool error or an observer hook failure; 1 for an incomplete response, a final response truncated by the output token limit, or a failed request; 2 for invalid provider configuration, plugin activation failure, or a login response without a key; and 130 for a cancelled request. Already streamed text remains on stdout if the final response is truncated. In a session the highest status from its turns is returned. HTTP failures are reported by status or exception type, and malformed JSON is reported without its contents. Other exceptions propagate from the Julia task.

This is not Pi's full-screen editor. Slash commands beyond `/exit`, `/tree`, and `/resume`, streaming tool output, live steering, follow-up queues, external-editor integration, and terminal controls for cancellation are unsupported. Alt+Enter and Ctrl+G report the corresponding unsupported actions while preserving the current input. The terminal waits for each request to finish; typing before the next prompt is displayed can be buffered or transformed by the terminal and is not a steering or follow-up queue. The editor uses Julia 1.12 REPL internals and ANSI terminal control sequences, so terminal and multiplexer behavior can differ. Its macOS pseudo-terminal tests use a synthetic provider and cover editing, Unicode input, multiline input, paste, history, Ctrl+C/Ctrl+D, stream redirection, and terminal-mode restoration. They do not verify visual rendering, resize, real terminal applications, another operating system, or a real provider. With `PI_SOURCE` configured, session discovery, recent selection, branch contexts, and retained user and assistant text are compared with the pinned Pi session manager, and truncated final output and status are compared with Pi's print mode using a scripted session; these do not test Pi's terminal UI or a live provider.
