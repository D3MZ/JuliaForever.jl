# Terminal

The `jf` command accepts a prompt in its arguments. With no prompt, TTY stdin and stderr and a `TERM` other than empty or `dumb` enable Julia's line editor. Enter sends a message; Ctrl+J inserts a newline. The editor also recognizes Shift+Enter when a terminal already sends `CSI 13;2u` or `CSI 27;2;13~`; `jf` does not enable extended keyboard protocols and terminals may send plain Enter instead. Arrow keys edit the input. Up and Down move between lines, then browse earlier or newer submitted prompts at the input boundaries. Drafts are restored when moving back down. Bracketed paste is inserted as one input, with CRLF or CR normalized to LF; spaces and tabs in the pasted text are retained. Ctrl+C clears the current input, and Ctrl+D exits if the input is empty or deletes forward otherwise. `/exit` ends the session.

Prompt history is held in memory for the current process only, separately from `--history` conversation storage. It can contain sensitive prompt text. The editor uses stderr; stdout may be redirected. If stdin is not a TTY, stderr is not a TTY, or `TERM` is unset or `dumb`, `jf` uses line-oriented input instead. Piped input sends one message per line and displays no banner or prompt. A TTY with the editor disabled still displays the banner and prompt on stderr. The same agent and conversation are retained across messages in one process.

Use `jf --history session.sqlite 'first prompt'`, then `jf --history session.sqlite 'next prompt'` to record and resume a conversation. The file holds one history; without `--history`, the conversation is only retained for the current process. SQLite.jl is installed with JuliaForever. The initial project instructions are retained in the history; resuming uses the current provider, tool configuration, and working directory. The file can contain conversation text, instructions, tool calls and results, so protect it as you would the conversation.

Use `--plugin PACKAGE` to load an explicitly selected native Julia plugin, and `--plugin-env PATH` to add a Julia environment containing it. Both options may be repeated before the prompt. The package must already be available and runs with your permissions. See [extensions](extensions.md) for the package interface, hook diagnostics, and limitations.

If a prior turn has a pending effect or is incomplete, the CLI exits with a diagnostic before requesting the provider or running a tool. It never automatically retries the effect. Run `jf --history session.sqlite --inspect-history` to display the recorded pending effects and tool arguments, and inspect external state before deciding what happened. Then record an explicit decision with `jf --history session.sqlite --abandon 'inspected external state'`. Neither command requires provider configuration or dispatches a request or tool. Abandoning records the reason but does not undo an effect. Reopen the CLI with the same path to start a new turn.

The inspection output can contain sensitive tool arguments. Abandonments recorded by older versions as `Interrupt` events can lack matching tool replies, which strict providers may reject. See [history storage](history.md) for database and platform limitations. Concurrent changes may cause a revision rejection; reopen and inspect before proceeding.

Assistant text is written and flushed as it arrives on stdout, with a newline after each assistant message when needed. Tool starts and outcomes go to stderr; successful tool output and tool arguments are not displayed. Tool errors are displayed with the configured provider key redacted. Incomplete responses are reported without the provider's raw error payload. Raw provider events and HTTP response bodies are not intentionally logged; recognized HTTP and malformed JSON failures omit their details. Assistant text is output as received and is not filtered. The `--login-openrouter` flow writes its authorization URL and code prompt to stdout; `--login-openrouter-callback` writes an authorization URL and waits for a local browser callback.

The command returns 0 after a completed response, including one that recovered from a tool error or an observer hook failure; 1 for an incomplete response or failed request; 2 for invalid provider configuration, plugin activation failure, or a login response without a key; and 130 for a cancelled request. In a session the highest status from its turns is returned. HTTP failures are reported by status or exception type, and malformed JSON is reported without its contents. Other exceptions propagate from the Julia task.

This is not Pi's full-screen editor. Slash commands beyond `/exit`, session selection, streaming tool output, live steering, follow-up queues, external-editor integration, and terminal controls for cancellation are unsupported. Alt+Enter and Ctrl+G report the corresponding unsupported actions while preserving the current input. The terminal waits for each request to finish; typing before the next prompt is displayed can be buffered or transformed by the terminal and is not a steering or follow-up queue. The editor uses Julia 1.12 REPL internals and ANSI terminal control sequences, so terminal and multiplexer behavior can differ. Its macOS pseudo-terminal tests use a synthetic provider and cover editing, Unicode input, multiline input, paste, history, Ctrl+C/Ctrl+D, stream redirection, and terminal-mode restoration. They do not verify visual rendering, resize, real terminal applications, another operating system, or a real provider. With `PI_SOURCE` configured, the retained user and assistant text is compared with the pinned Pi session manager; this does not test Pi's terminal UI.
