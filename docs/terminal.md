# Terminal

The `Terminal` compatibility properties `streamed` and `lineopen` remain Boolean and writable. Its internal presentation and line fields now use typed states, so direct field access and old Julia `Serialization` layouts are not compatible.

The `jf` command accepts a prompt in its arguments. With no prompt, an interactive terminal uses Julia's line editor: Enter sends; Ctrl+J, Shift+Enter where supported, or a trailing backslash followed by Enter adds a line; and arrow keys edit or recall prompts. Bracketed paste preserves multiline text. Ctrl+C clears the editor; pressing it again exits. Ctrl+D deletes forward, or exits when the editor is empty. The banner and editor are written to stderr. Piped input reads one message per line without a banner; `/exit` ends either session. The same agent and conversation are retained between messages.

While a request is active, Enter queues steering and Alt+Enter queues a follow-up; Ctrl+Q also queues a follow-up. Alt+Up returns queued messages to the editor. Escape interrupts the active request and restores queued input to the editor. `/new`, `/resume`, `/tree`, `/fork`, and `/clone` interrupt the request before changing sessions or opening a selector; `/name` does not. These controls require a supported interactive terminal.

Prompt history is held in memory for the current process only, separately from `--history` conversation storage. It can contain sensitive prompt text. The editor uses stderr; stdout may be redirected. If stdin is not a TTY, stderr is not a TTY, or `TERM` is unset or `dumb`, `jf` uses line-oriented input instead. Piped input sends one message per line and displays no banner or prompt. A TTY with the editor disabled still displays the banner and prompt on stderr. The same agent and conversation are retained across messages in one process.

Use `--provider` to select `openai`, `openai-responses`, `openrouter`, `anthropic`, or `google`. The flag overrides `JF_PROVIDER`, whose default is `openai`. `--model MODEL_ID` overrides the selected provider's model environment variable. IDs are passed literally; no catalog or fuzzy matching is performed. If either option is repeated, the last value wins. Set the selected provider's API key. Place options before the prompt. `--login-openrouter` and `--login-openrouter-callback` select OpenRouter and accept `--model` in any option order; if `--provider` is present with either login option, it must be `openrouter`.

The CLI saves a new SQLite session automatically when its first turn starts. Use `jf --continue` (or `-c`) to open the most recently modified session for the current working directory; if none exists, it starts a new session. Use `jf --resume` (or `-r`) to choose a project session from a numbered list, or `jf --session PATH|ID` to open an existing session by path or unique ID fragment. `jf --fork PATH|ID` copies its complete history to a separate session; a unique ID can also identify a session from another project. During a conversation, `/resume` switches sessions and `/new` starts a fresh session with reloaded project instructions. Enter `q` or an empty line to cancel the selector. `jf --no-session` starts in memory; a session selected with `/resume` is saved. The selector is line-oriented and does not yet support Pi's search, rename, delete, sorting controls, or cross-project browsing.

Use `/name NAME` or `jf --name NAME` (or `-n NAME`) to name the current session. `/name` displays the current name, or usage when unnamed. The name appears in the resume picker; naming an automatically saved session before its first turn does not create a file. Names are retained across branches and reopening.

If `/resume` rejects a selection or encounters an expected filesystem error while opening it, the current session remains active. A current session with a fault or unprocessed queued inputs cannot be switched away from; `/tree`, `/fork`, and `/clone` also block changes in that state. Malformed sessions appear as “Unavailable session” in the selector, and selecting one reports the history error. Other exceptions propagate.

Resume from the original project directory and select the required plugins and tool options again. The saved system context, including its working directory, instructions, and tool descriptions, is not regenerated; built-in tools operate in the current working directory, and current flags determine the plugins and tools available. Both `--session PATH` and `--history PATH` can open a history from another project, so resuming from a different directory can cause tools to modify the wrong project. Existing histories do not store a reliable structured original directory, and the CLI cannot detect this mismatch.

Use `--plugin PACKAGE` to load an explicitly selected native Julia plugin, and `--plugin-env PATH` to add a Julia environment containing it. Both options may be repeated before the prompt. The package must already be available and runs with your permissions. See [extensions](extensions.md) for the package interface, hook diagnostics, and limitations.

Sessions are stored under `~/.julia/juliaforever/sessions` by default. Set `JF_SESSION_DIR` or pass `--session-dir DIR` to use another directory; the flag takes precedence. Sessions for different working directories remain separate even in a shared directory. The CLI creates an automatic session file only when a turn starts, with owner-only file permissions. Paths and IDs refer to Julia Forever's SQLite histories, not Pi's JSONL files.

Enter `/tree` between turns to list the session's user messages and completed assistant responses, including other branches. Selecting a user message offers it for editing; submitting it starts a new branch. An empty edit keeps the original text, and `/cancel` aborts. Selecting an assistant response moves to that point and waits for the next message. `q` cancels the selector. Other branches remain in the history. A selection takes effect in the current process; reopening selects the last appended branch, as in Pi. The selector is line-oriented and does not yet support Pi's full tree UI, branch summaries, or selecting intermediate tool entries.

Enter `/fork` to choose a previous user message, including delivered steering and follow-ups, and create a separate session from the conversation before it. The selected text returns to the editor for revision; piped input prompts for the revised text. `/clone` creates a separate session containing the active branch. Forking and cloning leave the source history intact. The selector is line-oriented, and copies do not yet record Pi parent-session metadata.

`jf --history session.sqlite 'first prompt'`, followed by `jf --history session.sqlite 'next prompt'`, continues to record and resume an explicitly chosen file. The file holds one history; a standalone history is not added to automatic session discovery. SQLite.jl is installed with JuliaForever. Initial project instructions are retained in the history; resuming uses the current provider, tool configuration, and working directory. Session files can contain conversation text, instructions, tool calls and results, so protect them as you would the conversation. Place options before the prompt.

If a prior turn has a pending effect or is incomplete, the CLI exits with a diagnostic and the history file path before requesting the provider or running a tool. It never automatically retries the effect. Run `jf --history PATH --inspect-history` to display the recorded pending effects and tool arguments, and inspect external state before deciding what happened. Then record an explicit decision with `jf --history PATH --abandon 'inspected external state'`. Neither command requires provider configuration or dispatches a request or tool. Abandoning records the reason but does not undo an effect. Reopen the session to start a new turn.

If a restored history still has queued steering or follow-up messages, the CLI reports them and refuses a new prompt. A `/resume` or `/tree` selection with queued messages is refused and leaves the current session unchanged. Saved messages remain in the history; messages in an ephemeral session exist only in memory. Start a new session to resubmit messages after reviewing them.

The inspection output can contain sensitive tool arguments. Abandonments recorded by older versions as `Interrupt` events can lack matching tool replies, which strict providers may reject. See [history storage](history.md) for database and platform limitations. Concurrent changes may cause a revision rejection; reopen and inspect before proceeding.

Assistant text is written and flushed as it arrives, with a newline after each assistant message when needed. When both output streams are terminals, the live transcript and editor are redrawn on stderr; redirected stdout receives assistant text directly. Tool starts and outcomes go to stderr; successful tool output and tool arguments are not displayed. For valid text, tool errors and session diagnostics redact the configured provider key in raw text and standard single-layer Julia `repr` strings; other encodings and repeated escaping are not decoded. Incomplete responses are reported without the provider's raw error payload. Raw provider events and HTTP response bodies are not intentionally logged; recognized HTTP and malformed JSON failures omit their details. Assistant text is output as received and is not filtered. The `--login-openrouter` flow writes its authorization URL and code prompt to stdout; `--login-openrouter-callback` writes an authorization URL and waits for a local browser callback.

The command returns 0 after a completed response, including one that recovered from a tool error or an observer hook failure; 1 for an incomplete response, a final response truncated by the output token limit, or a failed request; 2 for invalid provider configuration, plugin activation failure, or a login response without a key; and 130 for a cancelled non-interactive request. Already streamed text remains visible if the final response is truncated. In a line-oriented session the highest status from its turns is returned; an interactive Escape cancellation does not make an otherwise successful session fail. HTTP failures are reported by status or exception type, and malformed JSON is reported without its contents. Other exceptions propagate from the Julia task.

The editor uses the terminal's normal scrollback, not Pi's full-screen display. Slash commands beyond `/exit`, `/new`, `/name`, `/tree`, `/resume`, `/fork`, `/clone`, and `/compact`, streaming tool output, and Pi's full set of controls remain absent. Synthetic mock and loopback tests cover the documented behavior. On Unix with Python 3, PTY tests exercise multiline editing, paste, prompt recall, session switching, branching, redirected output, and terminal restoration. An isolated tmux test also checks live queues, cancellation, redraw, resize, and SQLite reopening when tmux is available. With `PI_SOURCE` configured, selected editor inputs and session names are compared with pinned Pi. A real-provider interactive session and Windows terminal behavior have not been verified against Pi.

Shell progress reports the byte count of the currently available bounded output; it is not the full shell text.
