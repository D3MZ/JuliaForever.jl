# Terminal

The `jf` command accepts a prompt in its arguments. With no prompt, an interactive terminal uses Julia's line editor: Enter sends; Ctrl+J, Shift+Enter where supported, or a trailing backslash followed by Enter adds a line; and arrow keys edit or recall prompts. Bracketed paste preserves multiline text. Ctrl+C clears the editor; pressing it again exits. Ctrl+D deletes forward, or exits when the editor is empty. The banner and editor are written to stderr. Piped input reads one message per line without a banner; `/exit` ends either session. The same agent and conversation are retained between messages.

While a request is running, Enter queues a steering message and Alt+Enter queues a follow-up; Ctrl+Q also queues a follow-up. Alt+Up returns queued messages to the editor. Escape cancels the request and restores queued messages ahead of the current draft. Built-in provider requests and in-process Unix shell calls are interrupted; other work stops at its next cancellation boundary. A cancelled partial assistant response is displayed but is not retained in the conversation context. `/resume` and `/tree` interrupt the current request before opening their selectors. A prompt supplied as a command-line argument remains non-interactive.

Prompt templates are loaded at startup and expanded for command-line, interactive, steering, and follow-up prompts.

The CLI saves a new SQLite session automatically when its first turn starts. Use `jf --continue` (or `-c`) to open the most recently modified session for the current working directory; if none exists, it starts a new session. Use `jf --resume` (or `-r`) to choose a project session from a numbered list, or `jf --session PATH|ID` to open an existing session by path or unique ID fragment. During a conversation, `/resume` opens the same selector and switches to the chosen session. Enter `q` or an empty line to cancel the selector. `jf --no-session` keeps the initial conversation in memory; if you use `/resume`, subsequent messages are saved in the chosen session. The selector is line-oriented and does not yet support Pi's search, rename, delete, sorting controls, or cross-project browsing.

Sessions are stored under `~/.julia/juliaforever/sessions` by default. Set `JF_SESSION_DIR` or pass `--session-dir DIR` to use another directory; the flag takes precedence. Sessions for different working directories remain separate even in a shared directory. The CLI creates a session file only when a turn starts, with owner-only file permissions. Paths and IDs refer to Julia Forever's SQLite histories, not Pi's JSONL files.

Enter `/tree` between turns to list the session's user messages and completed assistant responses, including other branches. Selecting a user message offers it for editing; submitting it starts a new branch. An empty edit keeps the original text, and `/cancel` aborts. Selecting an assistant response moves to that point and waits for the next message. `q` cancels the selector. Other branches remain in the history. A selection takes effect in the current process; reopening selects the last appended branch, as in Pi. The selector is line-oriented and does not yet support Pi's full tree UI, branch summaries, or selecting intermediate tool entries. Naming and forking are also not implemented.

`jf --history session.sqlite 'first prompt'`, followed by `jf --history session.sqlite 'next prompt'`, continues to record and resume an explicitly chosen file. The file holds one history; a standalone history is not added to automatic session discovery. SQLite.jl is installed with JuliaForever. Initial project instructions are retained in the history; resuming uses the current provider, tool configuration, and working directory. Session files can contain conversation text, instructions, tool calls and results, so protect them as you would the conversation. Place options before the prompt.

If a prior turn has a pending effect or is incomplete, the CLI exits with a diagnostic and the history file path before requesting the provider or running a tool. It never automatically retries the effect. Run `jf --history PATH --inspect-history` to display the recorded pending effects and tool arguments, and inspect external state before deciding what happened. Then record an explicit decision with `jf --history PATH --abandon 'inspected external state'`. Neither command requires provider configuration or dispatches a request or tool. Abandoning records the reason but does not undo an effect. Reopen the session to start a new turn.

The inspection output can contain sensitive tool arguments. Abandonments recorded by older versions as `Interrupt` events can lack matching tool replies, which strict providers may reject. See [history storage](history.md) for database and platform limitations. Concurrent changes may cause a revision rejection; reopen and inspect before proceeding.

Assistant text is shown as it arrives, with a newline after each assistant message when needed. When both output streams are terminals, the live transcript and editor are redrawn on stderr; redirected stdout receives assistant text directly. Tool starts and outcomes go to stderr; successful tool output and tool arguments are not displayed. Tool errors are displayed with the configured provider key redacted. Incomplete responses are reported without the provider's raw error payload. Raw provider events and HTTP response bodies are not intentionally logged; recognized HTTP and malformed JSON failures omit their details. Assistant text is output as received and is not filtered. The `--login-openrouter` flow writes its authorization URL and code prompt to stdout; `--login-openrouter-callback` writes an authorization URL and waits for a local browser callback.

The command returns 0 after a completed response, including one that recovered from a tool error; 1 for an incomplete response or failed request; 2 for invalid provider configuration or a login response without a key; and 130 for a cancelled non-interactive request. In a line-oriented session the highest status from its turns is returned; an interactive Escape cancellation does not make an otherwise successful session fail. HTTP failures are reported by status or exception type, and malformed JSON is reported without its contents. Other exceptions propagate from the Julia task.

The editor uses the terminal's normal scrollback, not Pi's full-screen display. Slash commands beyond `/exit`, `/tree`, and `/resume`, streaming tool output, and Pi's full set of controls remain absent. Synthetic mock and loopback tests cover the documented behavior. On Unix with Python 3, PTY tests exercise multiline editing, paste, prompt recall, session switching, branching, redirected output, and terminal restoration. An isolated tmux test also checks live queues, cancellation, redraw, resize, and SQLite reopening when tmux is available. With `PI_SOURCE` configured, selected editor inputs are compared with the pinned Pi editor. A real-provider interactive session and Windows terminal behavior have not been verified against Pi.
