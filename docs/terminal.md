# Terminal

The `Terminal` compatibility properties `streamed` and `lineopen` remain Boolean and writable. Its internal presentation and line fields now use typed states, so direct field access and old Julia `Serialization` layouts are not compatible.

The `jf` command accepts a prompt in its arguments. With no prompt and terminal input and output, it opens a full-screen transcript with Julia's line editor. Enter sends; Ctrl+J, Shift+Enter where supported, or a trailing backslash followed by Enter adds a line; and arrow keys edit or recall prompts. Bracketed paste preserves multiline text. Ctrl+C clears the editor; pressing it again exits. Ctrl+D deletes forward, or exits when the editor is empty. The screen is written to stderr. Piped input reads one message per line without a banner; `/exit` ends either session. The same agent and conversation are retained between messages.

Page Up and Page Down scroll the transcript, and Ctrl+Home and Ctrl+End jump to the beginning and end. Ctrl+O expands or collapses tool arguments and output. The footer shows the current model, activity, session name, and working directory. Ctrl+L opens a searchable picker of bundled models for the current provider, with an option to enter a model ID. `/model ID` also changes models within the current provider. Model changes apply to this process and do not persist as session settings; the picker retains the current API configuration. See [model catalog](models.md) for its freshness and availability limits. `/resume`, `/tree`, and `/fork` open searchable lists in the full-screen interface; use arrow keys, Enter, and Escape to select or cancel.

Typing `/` at the start of a message opens fuzzy suggestions for available built-in commands, prompt templates, and skills, including skills reserved for explicit invocation. Up and Down select an item, Tab inserts it, Enter inserts and submits it, and Escape dismisses the list. Page Up and Page Down move through the list in full-screen mode. Skill suggestions follow `/new` and successful `/reload`; prompt-template suggestions use the startup snapshot.

Typing `@` at a token boundary searches for matching files and directories recursively. Tab also completes ordinary paths, including quoted names and home-relative paths. For file suggestions, Tab or Enter inserts the selection without submitting the prompt. Searches follow directory symlinks with cycle protection and consult `.gitignore`, `.ignore`, and `.fdignore`; they return at most 20 suggestions from the first 100 matches. The native search does not reproduce every `fd` ignore or ranking rule. Interactive completion inserts a path as text; the separate `@PATH` CLI argument described below includes file contents. Command arguments do not yet have completion.

While a request is active, Enter queues steering and Alt+Enter queues a follow-up; Ctrl+Q also queues a follow-up. Alt+Up returns queued messages to the editor. Escape interrupts the active request and restores queued input to the editor. `/new`, `/resume`, `/tree`, `/fork`, `/clone`, `/compact`, and `/model` interrupt the request before running the command; `/name` does not. `/reload` requires an idle session and warns without interrupting an active response. These controls require a supported interactive terminal.

Prompt history is held in memory for the current process only, separately from `--history` conversation storage. It can contain sensitive prompt text. Use `--tui-mode regular` for the line editor with terminal scrollback; `--tui-mode fullscreen` is the default. If stdout is redirected, `jf` uses the regular editor and writes assistant text to stdout. If stdin or stderr is not a TTY, or `TERM` is unset or `dumb`, `jf` uses line-oriented input. Piped input sends one message per line and displays no banner or prompt. A TTY with the editor disabled still displays the banner and prompt on stderr.

Use `@PATH` to include files in the initial prompt, for example `jf @notes.txt @diagram.png 'Explain these'`. Paths resolve from the working directory. Text files are included in order with their absolute paths; PNG, JPEG, GIF, and WebP files are attached as images. Empty files are skipped. Piped input is trimmed and placed before the files and first message; additional positional messages are sent as later turns. A missing or unreadable file stops the request. Images are not resized, and BMP conversion is not available. For arguments without `@PATH`, the existing line-oriented and positional-input behavior applies.

Use `--provider` to select `openai`, `openai-responses`, `openrouter`, `anthropic`, or `google`. The flag overrides `JF_PROVIDER`, whose default is `openai`. Use `--list-models [search]` to see models for configured providers and `--model MODEL` to resolve a model reference or provide a custom ID. Recognized OpenAI catalog models use Responses. If either option is repeated, the last value wins. Set the selected provider's API key. Options can appear alongside positional messages; `--` ends option parsing. `--login-openrouter` and `--login-openrouter-callback` select OpenRouter and accept `--model` in any option order; if `--provider` is present with either login option, it must be `openrouter`. See [models](models.md) for selection and catalog limitations.

Use `--mode json` for a one-shot JSONL event stream. It emits a session header and live message and tool events, with diagnostics on stderr. Piped stdin is combined with the first prompt; subsequent arguments are separate turns. Failed or truncated model responses are represented in the stream and do not by themselves make the process exit nonzero. See [JSON mode](json-mode.md) for event details and compatibility limits.

The default built-in tools are `read`, `bash`, `edit`, and `write`; loaded plugin tools are also enabled. Use `--tools LIST` (or `-t LIST`) for a comma-separated allowlist, where `*` matches any characters; `--tools +grep,-write` changes the default built-in selection instead. Names and `+`/`-` modifiers cannot be mixed, and modifiers use exact names. `--exclude-tools LIST` (or `-xt LIST`) removes matching tools after selection. `--no-builtin-tools` (`-nbt`) leaves plugin tools enabled; `--no-tools` (`-nt`) disables all tools unless an explicit `--tools` selection enables them. Repeated valid lists use the last value; an invalid `--tools` list is rejected even if followed by a valid one. Plugin hooks still run when their tools are disabled. Search tools `ls`, `find`, and `grep` and `powershell` are available through selection; PowerShell execution requires Windows.

`--codemode` registers the optional code tool; tool selection also controls which tools its `tools` interface exposes. Julia code itself runs with the user's permissions and is not sandboxed. Resuming an existing session retains its saved system context, so that context can describe earlier tools even when the current selection differs; only currently selected tools are callable.

The CLI saves a new SQLite session automatically when its first turn starts, or when `/reload` changes its skill context. Use `jf --continue` (or `-c`) to open the most recently modified session for the current working directory; if none exists, it starts a new session. Use `jf --resume` (or `-r`) to choose a project session from a numbered list, or `jf --session PATH|ID` to open an existing session by path or unique ID fragment. `jf --fork PATH|ID` copies its complete history to a separate session; a unique ID can also identify a session from another project. During a conversation, `/resume` switches sessions and `/new` starts a fresh session with reloaded project instructions. Enter `q` or an empty line to cancel a numbered selector. `jf --no-session` starts in memory; a session selected with `/resume` is saved. The full-screen selector supports search, but not Pi's rename, delete, sorting controls, or cross-project browsing.

Enter `/reload` between turns to rediscover skills from the same project and user roots used at startup. The managed skill metadata in the model's system context is replaced, including removal when no visible skills remain; skill bodies are not included in the system context. The prior conversation and existing history entries remain intact, and the change is recorded on the active branch for subsequent requests and resume. An unchanged reload does not write a history entry. A history fault, incomplete turn, or queued inputs blocks the change. If discovery or history writing encounters a filesystem error, it reports the failure with the provider key redacted and leaves the prior context intact; a history write with an uncertain outcome marks the session faulted. Other exceptions propagate. Reopened histories retain their recorded metadata until `/reload`; use the intended project directory because discovery uses the current directory.

Discovery searches `.pi/skills` in the working directory, `.agents/skills` in that directory and its ancestors through the first Git root, `skills` in `PI_CODING_AGENT_DIR` (default `~/.pi/agent`), and `~/.agents/skills`. It keeps the first skill of each name, warns on collisions, and omits skills marked `disable-model-invocation: true` from the model-facing section. Invalid or missing descriptions are skipped. This follows Julia Forever's existing discovery rules rather than Pi's configurable package and resource paths.

Use `/skill:NAME` with optional arguments to send a discovered skill's instructions and its reference directory as the user message. Explicit invocation also works for skills hidden from automatic model selection. The skill list is captured at startup and refreshed by `/new` or a successful `/reload`; the file body is read when the command is submitted. Unknown skills pass through as ordinary input. If a known skill cannot be read or parsed, the CLI warns and sends the original input. Queued steering and follow-ups expand when queued, and JSON mode uses the same expansion.

This is a skills-only subset of Pi's `/reload`: it does not refresh instructions, prompt templates, plugins, settings, tools, themes, or trust. Pi also gates model-visible skills on access to a reader, while Julia Forever currently advertises discovered visible skills regardless of tool selection. Pi's full resource diagnostics remain unsupported. Existing recorded CLI skill sections are recognized in their original position; directly editing or moving an unmarked recorded section can prevent its identification. The differential fixtures check Pi revision `e7a0df27c09d11bf4161d3605246cbf57a129cb2` for skill commands, metadata and session messages; native tests also cover provider requests, SQLite resume, busy input, and failures.

Tool calls in a model response run in parallel by default. Calls that have started may finish after cancellation; saved sessions retain completed observations and report unresolved effects on reopening.

Use `/name NAME` or `jf --name NAME` (or `-n NAME`) to name the current session. `/name` displays the current name, or usage when unnamed. The name appears in the resume picker; naming an automatically saved session before its first turn does not create a file. Names are retained across branches and reopening.

If `/resume` rejects a selection or encounters an expected filesystem error while opening it, the current session remains active. A current session with a fault or unprocessed queued inputs cannot be switched away from; `/tree`, `/fork`, and `/clone` also block changes in that state. Malformed sessions appear as “Unavailable session” in the selector, and selecting one reports the history error. Other exceptions propagate.

Resume from the original project directory and select the required plugins and tool options again. The saved system context, including its working directory, instructions, and tool descriptions, is not regenerated; built-in tools operate in the current working directory, and current flags determine the plugins and tools available. Both `--session PATH` and `--history PATH` can open a history from another project, so resuming from a different directory can cause tools to modify the wrong project. Existing histories do not store a reliable structured original directory, and the CLI cannot detect this mismatch.

Use `--plugin PACKAGE` to load an explicitly selected native Julia plugin, and `--plugin-env PATH` to add a Julia environment containing it. Both options may be repeated. The package must already be available and runs with your permissions. See [extensions](extensions.md) for the package interface, hook diagnostics, and limitations.

Sessions are stored under `~/.julia/juliaforever/sessions` by default. Set `JF_SESSION_DIR` or pass `--session-dir DIR` to use another directory; the flag takes precedence. Sessions for different working directories remain separate even in a shared directory. The CLI creates an automatic session file when a turn starts or changed skills are reloaded, with owner-only file permissions. Paths and IDs refer to Julia Forever's SQLite histories, not Pi's JSONL files.

Enter `/tree` between turns to list the session's user messages and completed assistant responses, including other branches. Selecting a user message offers it for editing; submitting it starts a new branch. An empty edit keeps the original text, and `/cancel` aborts. Selecting an assistant response moves to that point and waits for the next message. `q` cancels a numbered selector. Other branches remain in the history. A selection takes effect in the current process; reopening selects the last appended branch, as in Pi. Branch summaries and selecting intermediate tool entries are not supported.

Enter `/fork` to choose a previous user message, including delivered steering and follow-ups, and create a separate session from the conversation before it. The selected text returns to the editor for revision; piped input prompts for the revised text. `/clone` creates a separate session containing the active branch. Forking and cloning leave the source history intact. Copies do not yet record Pi parent-session metadata.

`jf --history session.sqlite 'first prompt'`, followed by `jf --history session.sqlite 'next prompt'`, continues to record and resume an explicitly chosen file. The file holds one history; a standalone history is not added to automatic session discovery. SQLite.jl is installed with JuliaForever. Initial project instructions are retained in the history; resuming uses the current provider, tool configuration, and working directory. Session files can contain conversation text, instructions, tool calls and results, so protect them as you would the conversation. Options can appear alongside positional messages; `--` ends option parsing.

If a prior turn has a pending effect or is incomplete, the CLI exits with a diagnostic and the history file path before requesting the provider or running a tool. It never automatically retries the effect. Run `jf --history PATH --inspect-history` to display the recorded pending effects and tool arguments, and inspect external state before deciding what happened. Then record an explicit decision with `jf --history PATH --abandon 'inspected external state'`. Neither command requires provider configuration or dispatches a request or tool. Abandoning records the reason but does not undo an effect. Reopen the session to start a new turn.

If a restored history still has queued steering or follow-up messages, the CLI reports them and refuses a new prompt. A `/resume` or `/tree` selection with queued messages is refused and leaves the current session unchanged. Saved messages remain in the history; messages in an ephemeral session exist only in memory. Start a new session to resubmit messages after reviewing them.

The inspection output can contain sensitive tool arguments. Abandonments recorded by older versions as `Interrupt` events can lack matching tool replies, which strict providers may reject. See [history storage](history.md) for database and platform limitations. Concurrent changes may cause a revision rejection; reopen and inspect before proceeding.

Assistant text is written and flushed as it arrives, with a newline after each assistant message when needed. When both output streams are terminals, the live transcript and editor are redrawn on stderr; redirected stdout receives assistant text directly. In full-screen mode, tool status is shown in the transcript and Ctrl+O reveals arguments and output. Regular mode shows tool starts and outcomes, but not successful output or arguments. For valid text, tool details and session diagnostics redact the configured provider key in raw text and standard single-layer Julia `repr` strings; other encodings and repeated escaping are not decoded. Incomplete responses are reported without the provider's raw error payload. Raw provider events and HTTP response bodies are not intentionally logged; recognized HTTP and malformed JSON failures omit their details. Full-screen rendering removes terminal control sequences from displayed text; redirected assistant text is output as received. The `--login-openrouter` flow writes its authorization URL and code prompt to stdout; `--login-openrouter-callback` writes an authorization URL and waits for a local browser callback.

The command returns 0 after a completed response, including one that recovered from a tool error or an observer hook failure; 1 for an incomplete response, a final response truncated by the output token limit, or a failed request; 2 for invalid provider configuration, plugin activation failure, or a login response without a key; and 130 for a cancelled non-interactive request. Already streamed text remains visible if the final response is truncated. In a line-oriented session the highest status from its turns is returned; an interactive Escape cancellation does not make an otherwise successful session fail. HTTP failures are reported by status or exception type, and malformed JSON is reported without its contents. Other exceptions propagate from the Julia task.

Pi's complete set of slash commands and controls, transcript search, clipboard integration, and inline image rendering remain absent. Synthetic mock and loopback tests cover the documented behavior. On Unix with Python 3, PTY tests exercise editing, session switching, branching, redirected output, and terminal restoration. Isolated tmux tests also check live queues, cancellation, redraw, resize, and SQLite reopening when tmux is available. With `PI_SOURCE` configured, selected editor inputs, alternate-screen and transcript scrolling behavior, and session names are compared with pinned Pi. A real-provider interactive session and Windows terminal behavior have not been verified against Pi.

Shell progress reports the byte count of the currently available bounded output; it is not the full shell text.
