# Terminal

The `jf` command accepts a prompt in its arguments. With no prompt it reads one message per input line and `/exit` ends the session. A terminal input displays a banner and prompt on stderr; piped input does not. The same agent and its conversation are retained for the lines in one process.

Assistant text is written and flushed as it arrives on stdout, with a newline after each assistant message when needed. Tool starts and outcomes go to stderr; successful tool output and tool arguments are not displayed. Tool errors are displayed with the configured provider key redacted. Incomplete responses are reported without the provider's raw error payload. Raw provider events and HTTP response bodies are not intentionally logged; recognized HTTP and malformed JSON failures omit their details. Assistant text is output as received and is not filtered. The `--login-openrouter` flow is interactive and additionally writes its authorization URL and code prompt to stdout.

The command returns 0 after a completed response, including one that recovered from a tool error; 1 for an incomplete response or failed request; 2 for invalid provider configuration or a login response without a key; and 130 for a cancelled request. In a line-oriented session the highest status from its turns is returned. HTTP failures are reported by status or exception type, and malformed JSON is reported without its contents. Other exceptions propagate from the Julia task.

This is a line-oriented interface, not Pi's full-screen editor. It has no multiline editing, slash commands beyond `/exit`, session selection, streaming tool output, live steering, or terminal controls for cancellation. The agent loop and stream callbacks run in one Julia task, and the terminal waits for each request to finish. Synthetic mock and loopback tests cover the documented behavior; a real-provider interactive terminal session has not been verified.
