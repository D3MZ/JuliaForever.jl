# Branch and dispatch audit

The audit covers Julia source in `src/`. `test/branch_scan.jl` uses JuliaSyntax to list source locations for conditionals, short-circuit expressions, loops, exception handlers, comprehension filters, `ifelse`, and calls that may take predicates. The predicate list can include calls whose first argument is a search value rather than a function. The inventory is a static review aid; it cannot see branches produced by arbitrary macro expansion or dynamic code.

At revision `b1a598e`, the inventory contained 1,270 points, including 73 `for` loops, 36 exception handlers, and 31 possible predicate calls. The integrated tree has 1,126 points. Counts include nested expressions, so they are not counts of independent decisions. `test/branch-baseline.txt` ratchets the normalized inventory, so added, removed, or changed entries require review and an explicit baseline update. It does not detect changes confined to branch bodies or moves of identical entries.

The dispatch check is a separate heuristic. With the expanded rules it reports 247 candidates in the integrated tree. The exact multiset is in `test/dispatch-baseline.txt`; tests fail if it grows or changes without updating the baseline. Four matches preserve the Boolean `Terminal.streamed` and `Terminal.lineopen` compatibility properties; their two behavioral flag checks were retired.

The string-status rule found 12 previously unrecognized checks in the provider-merge checkout. Eleven were removed through typed decoding; the remaining OAuth query-key comparison is not a behavioral status. The check also finds status-field and selection comparisons when they return or assign a Boolean instead of controlling a branch directly. A later pass extended this to `isa`, `isnothing`, `ismissing`, and Boolean or missing-value comparisons outside branch conditions; it exposed two additional checks, both replaced with dispatch. It also catches comparisons of `typeof(...)` outside branch conditions; this revealed no additional current candidates. The dynamic `Val(...)` and `Val{...}()` rule found four value-based type tags in the terminal editor; those were replaced with domain outcomes or ordinary numeric checks.

The remaining candidates are not all equivalent. Input validation, file-edit safety, numerical and collection checks, and compatibility accessors still require decisions at their boundaries. The agent loops still check cancellation, completion, and configuration status at a few points. Some provider and worker protocol decoders still branch on tags; these can be refactored further. The baseline records these candidates; it is not an assertion that every one is an acceptable exception. The largest remaining groups are MCP (37), search (30), durable storage (18), CodeMode (18), conversation codec (17), and system tools (17).

The review retained the edit checks for missing, ambiguous, and overlapping targets. Exception handlers were reviewed as protocol or operating-system failure boundaries, cleanup, and recovery paths. JuliaSyntax supplies source-aware inventory; JET and Aqua complement it with inference and package-quality tests, but they do not determine whether a branch should use dispatch.

Run the inventory in an environment containing JuliaSyntax with `julia test/branch_scan.jl`. The package test target installs JuliaSyntax and runs the branch and dispatch tests with `julia --project -e 'using Pkg; Pkg.test()'`.

The session integration added three branch entries and retired 53 against the multiset union of its two parents; it added no dispatch candidates and retired 21. Two added branch entries combine existing login and session-name restrictions for history recovery commands; the third is the argument-count check for the name option. The subsequent shell-streaming merge increased the branch inventory from 1,087 to 1,104 and left the dispatch inventory at 247. Compared with the union of its two parents, it added no branch or dispatch entries and retired 83 branch entries and 54 dispatch candidates. The MCP resources merge increased the branch inventory to 1,126 and retained 247 dispatch candidates. Against the two parent inventories it added one heuristic entry: a second `count > ...` check, now present independently in image handling and resource pagination.
