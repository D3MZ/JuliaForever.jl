# B1 surface and native design

Julia Forever is a native Julia agent harness and terminal application. B1 aims for the observable agent and coding surface of the pinned Pi reference. Pi is used to compare behavior during development; Julia Forever runs and deploys with the Julia runtime and does not depend on Pi or Node.js.

## Product surface

The B1 inventory covers the following areas. Existing tests exercise selected cases; this list is not a claim that any whole area has parity.

- Agent turns, streamed responses, tool calls, cancellation, steering, follow-ups, errors, usage and provider authentication.
- Terminal interaction, configuration, project instructions, sessions and history, including recovery and exports.
- File and shell tools, search, truncation and failure behavior on supported platforms.
- Native Julia code mode, native Julia extensions and the optional integrations needed by the user-facing surface.
- Persistent work and execution across Julia processes, with explicit recovery behavior for interrupted work.

Extensions are native Julia packages. Julia code mode accepts Julia programs.

## Architecture

Implement behavior using Julia types, multiple dispatch, tasks, channels and `Distributed` where they fit. Pi's internal event loop, object model, storage formats and deployment architecture are not requirements. Keep persistence and recovery concrete: record enough state to recover work, distinguish completed, pending and uncertain effects, and apply explicit retry or reconciliation policies. An external effect cannot be assumed to have failed just because a worker or coordinator disappeared.

Histories and replay should be accessible as Julia data. Storage and execution backends should be replaceable, and experiments should live separately from the harness. Prefer small APIs and ordinary Julia errors over speculative guards. Measure runtime and allocations before optimizing; performance claims require comparable benchmarks.

## Evidence

Compare Julia and Pi with identical deterministic fixtures for each included observable contract: returned results, errors, event ordering and filesystem effects where applicable. Pin both revisions and record any normalization or intentional difference. Use native tests for Julia-specific behavior, recovery, replay and concurrency. Test macOS, Linux and Windows independently; a configured CI job is not a passing result. B1 is complete only when the included surface is inventoried and each required area has passing evidence at the verified revisions.

See [architecture](architecture.md) for the current implementation and [the README](../README.md) for installation and test commands. Full B1 coverage, parity and performance are not yet established.
