# File editing

`Read` detects static PNG and JPEG by file signature, independent of extension. Images up to 10 MiB are returned as a `ToolResult` with an `Image(mime, data)` containing the original base64-encoded bytes; line offset and limit apply only to text. No resizing, conversion, or full image decoding is performed. Animated PNG, recognized GIF, WebP, BMP and JPEG-LS, structurally unsupported PNG, and oversized images return an explicit error without an attachment. Other binary formats are outside this detector and retain the existing text-read behavior. Pi supports more formats and automatic resizing; a selected PNG and JPEG comparison uses Pi with resizing disabled. Providers must support image input; there is no model capability catalog.

`Edit` matches each replacement against the same original text. It accepts a unique exact match or falls back to Unicode NFKC normalization, trailing line whitespace removal, and normalization of smart quotes, dashes, and special spaces. If any replacement needs fuzzy matching, matching is performed in the normalized text and only touched lines are rewritten from that text; untouched lines retain their original characters. All replacement targets must be unique and disjoint. Missing, ambiguous, overlapping, empty, or no-change edits leave the file untouched. Overlapping occurrences of a target are also ambiguous, even where Pi's non-overlapping occurrence count would accept them. A target that normalizes to empty is accepted only as a unique exact match when the entire normalized file is empty.

The file's UTF-8 BOM is preserved. Input and replacement line endings are normalized to LF for matching, then the entire file is written using CRLF if its first LF was part of CRLF, or LF otherwise. Mixed line endings therefore become uniform, matching Pi's selected behavior. The tests compare selected cases directly against Pi at the pinned revision; they do not establish full B1 parity. Julia and Pi may use different Unicode normalization versions. `Write` and `Edit` coordinate mutations within a Julia process. For each canonical path, registered operations run in order and the lock covers the entire write or edit, including the edit's read and match. Different paths may proceed concurrently. Existing symlinks, missing paths under symlinked directories, and dangling file symlinks are resolved to their target paths; registry entries are removed after the last operation, including on failure. Pi's queue uses the unresolved absolute path for a missing destination, so aliases of a new file may differ from this behavior.

Path identity is process-local and assumes links and files are not replaced or retargeted concurrently. Distinct hard links are not identified as one file; on case- or normalization-insensitive filesystems, differently spelled names for a file that does not yet exist may also get distinct locks. Other processes, `Read`, and external filesystem operations do not participate. Writes are not atomic replacements, so readers can observe an intermediate state. Pi's single-object and legacy input preparation, structured diff and patch details, custom file operations, abort handling, and exact error messages are not implemented here. Invalid UTF-8 and platforms other than macOS are unverified.
