# Automatic compaction

`JuliaForever.autocompact!(agent, usage, JuliaForever.AutoCompaction(context_window, reserve_tokens; enabled=true))` compacts when reported usage exceeds the reserve threshold. It returns `nothing` when disabled or the threshold is not crossed; otherwise it returns the compactor's result. A fourth argument supplies a summarizer. `respond!` accepts the same policy through `auto_compaction` and a `summarize` callable. After a successful turn it reports threshold compaction through `:auto_compaction_end`; its response remains the turn result.

For local, direct `respond!` calls, the enabled policy also recovers an unfinished `Completion` with `ProviderStatus(413)` or `ProviderError` kind `:request_too_large`, except when that error has status 429. It requires earlier non-summary history to compact. It compacts that history, retains system messages and the entire latest user turn, and retries once. A new user message or successful non-length assistant completion permits a later turn to recover independently. Disabled policies, other errors, no-progress plans, and a second overflow do not start a retry. Replacing the agent's provider before or during compaction prevents retry; replacement after the compaction commit leaves the committed summary intact. Callers must not mutate a custom provider's model in place during a run.

The failed incomplete assistant is observable through the existing message and turn events, but is not included in model context. With a `History.Store`, its observation and the compaction are recorded before retry dispatch; a reopened history does not automatically replay a pending effect. An unobserved, interrupted durable effect requires the existing explicit reconciliation and `abandon!` workflow. The incomplete observation retains assistant metadata, but not `Completion.error` or usage.

Overflow recovery emits `:auto_compaction_start` and `:auto_compaction_end` with `reason=:overflow`. The end event carries the summary, `:cancelled`, or a `History.Rejected` result; a second overflow reports `:overflow_retry_exhausted`. A summarizer failure or exception leaves the original overflow as the turn result and does not retry. A history fault is returned. Cancellation before commit prevents summary commit, and cancellation before dispatch prevents retry; the default summarizer also cancels its native HTTP request. Custom summarizers must cooperate to stop their own work.

## Pi comparison and remaining gaps

At pinned Pi revision `e7a0df27c09d11bf4161d3605246cbf57a129cb2`, recovery is enabled only for the matching model and a retained, relevant response after the latest compaction boundary. Explicit overflow errors and recoverable length stops omit the failed assistant and paired tool results from the durable projection, then attempt compaction and one continuation. If preparation has nothing to compact, the summarizer is not called. A second overflow emits a failure instead of another attempt. Pi resets the attempt on a new user message or a non-error, non-length assistant message. Cancellation, extension cancellation, or compaction failure prevents continuation. Successful responses whose input usage exceeds the context window compact without retry.

This slice does not implement Pi's complete message-pattern detection, silent overflow, recoverable length stops, model registry or virtual-model matching, token-based cut points, pre-prompt checks, context edits, paired-result omission for finished responses, compaction extension interception, or Pi's session lifecycle events. It does not recover `continue!` or executor-backed turns, and the terminal does not configure automatic compaction. HTTP bodies are deliberately redacted in Julia's `ProviderStatus`, so a 413 is treated as request-size overflow without inspecting a potentially rate-limiting body. Threshold checks still do not estimate missing or zero usage. See `docs/execution.md` for executor limitations.
