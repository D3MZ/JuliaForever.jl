# Headless JSON and RPC modes

`jf --mode json 'prompt'` writes a session header and live events as JSON lines and exits after the supplied prompts finish. `jf --mode rpc` reads one JSON command per line and writes responses and events as JSON lines until stdin closes. Stdout is reserved for protocol records; diagnostics and native plugin stdout go to stderr. RPC rejects `@file` arguments and interactive login or session selection. Use a session path, ID, `--continue`, or `--no-session` instead.

RPC commands may carry a string `id`, which is repeated on their responses. A successful `prompt` response reports `started` or `queued`; wait for `agent_settled` before assuming the run has completed. While a prompt runs, `steer` and `follow_up` queue messages, and `abort` requests cancellation and waits for the run to finish. A second `prompt` needs `streamingBehavior` set to `steer` or `followUp`. Closing stdin stops output, requests cancellation and waits for active work.

The implemented commands are `prompt`, `steer`, `follow_up`, `abort`, `clear_queue`, `new_session`, `switch_session`, `clone`, `get_fork_messages`, `fork`, `export_html`, `get_state`, `get_messages`, `get_entries`, `get_tree`, `get_commands`, `get_session_stats`, `get_last_assistant_text`, `set_session_name`, `get_available_thinking_levels`, `cycle_thinking_level`, `set_thinking_level`, `set_steering_mode`, `set_follow_up_mode`, `set_auto_compaction`, `set_auto_retry`, `abort_retry`, `bash`, and `abort_bash`. Command discovery lists Julia's prompt templates and skills; it does not list Pi's built-in extension commands. RPC can start without a complete model and key configuration, but rejects prompts until restarted with configuration. If no providers have keys, model listing returns an empty list; listing configured providers is not yet supported. Thinking controls support mapped OpenAI Responses levels, including configuration updates where the native provider permits them, and selected Gemini and Anthropic levels described in [models](models.md). Routes with configured provider overrides or unsupported authorization have fewer levels than Pi. Other providers expose only `off`. Both queues support `one-at-a-time` and `all`, and their modes follow the current RPC session and its saved history. Pi also saves mode changes as global settings, which Julia Forever does not currently do. `switch_session` opens existing Julia session files or IDs; Pi also accepts nonexistent paths. For earlier sessions without RPC entry metadata, fork discovery uses native session-tree identifiers. HTML export uses Julia Forever's simple transcript view. Enabling automatic compaction or retry and setting a parent for `new_session` are not supported. Other Pi commands return an unsupported-command response.

On Unix, `bash` streams sanitized output as `bash_execution_update` events, records the result in the session, and honors `excludeFromContext`. `abort_bash` cancels active shell commands. Output exceeding the shell limits retains a full-output file. Shell-only sessions stay in memory until a conversation starts. RPC shell execution is unavailable on Windows because the native shell runner does not support cancellation there. Pi extension-provided shell operations and shell settings are not yet supported.

`get_entries` and `get_tree` expose recorded model, thinking, message, and session-name entries with stable IDs, parent links, and timestamps. `get_entries` accepts a `since` ID. Fork discovery uses the same IDs for user messages recorded by RPC. Entries recorded by RPC survive reopening; earlier Julia sessions do not contain RPC entry metadata and are not reconstructed as Pi entries.

The JSON and RPC event streams follow the selected Pi event shapes for agent, turn, message, text, thinking, tool and queue events. Initial prompts can contain images; tool results can carry images. Expected provider transport failures produce an assistant error and `agent_settled`. Provider error details are intentionally summarized instead of exposing raw provider payloads. Native plugin output is routed to stderr, but plugins are trusted Julia code and can still bypass ordinary output handling.

This is not full Pi protocol parity. The model object in `get_state` contains the known ID, provider, API and base URL, but omits catalog details. It does not implement RPC model changes, extension UI, or the retry and compaction event protocols. Automatic compaction is disabled in RPC mode. The session ID follows Julia's JSON-mode session ID, and saved sessions use SQLite rather than Pi JSONL. `get_session_stats` fails when prior usage or model pricing is unavailable, rather than returning incomplete totals; context-window usage is omitted.

The Julia history does not retain Pi's message timestamps, model metadata, usage or cost for earlier turns. Reopened messages therefore omit those unavailable fields. Recorded user and assistant text and tool calls and results are restored, but historical thinking and original content-block ordering may be lost. Current responses contain reported token counts and total cost when available, but the provider API does not expose Pi's cost breakdown. Initial system messages reflect Julia's own context rather than Pi's system sections and tool-change records. Some provider streams do not preserve original content-block boundaries, so interleaved thinking, text and tool-call blocks can differ from Pi's indices and ordering; tool durations and some provider-specific metadata are also absent.

Focused subprocess comparisons use Pi revision `e7a0df27c09d11bf4161d3605246cbf57a129cb2` with a local synthetic provider. They cover text and tool streams, queueing, cancellation, session reopening, stdout isolation, and selected failures. They do not establish full protocol, provider, cross-platform or live-service parity.

RPC `steer`, `follow_up`, and streaming `prompt` accept images and preserve them in recorded queues. Queue update events expose text only, matching Pi. Because Pi’s `clear_queue` response contains only text, Julia Forever refuses to clear a queue containing images, leaving the entire queue intact. Session transitions also refuse pending inputs. Images remain in recorded session data; an image-capable provider is required.
