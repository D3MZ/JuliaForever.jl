# ChatGPT plan sign-in

The CLI can use the [OpenAI ChatGPT plan sign-in flow](https://developers.openai.com/siwc/token-sharing-open-source) on Unix. If no provider or OpenAI API key is configured, `jf` in a terminal offers to continue with ChatGPT. An explicitly selected catalog model from another provider uses that provider; for example, `jf --model openrouter/free` uses a saved OpenRouter key and reports a missing key when none is configured. Use `jf --login-chatgpt` to sign in explicitly, reauthorize, or add another account. A saved account is reused on later launches; if several accounts exist, select one. `jf --logout-chatgpt` signs out of the selected account and attempts to revoke its refresh token. If revocation cannot be confirmed, the CLI clears local tokens and reports that fact.

The browser asks for permission to use the selected ChatGPT plan. A subscription alone does not guarantee eligibility or model access. No API key is used or required by this flow. On sign-in the CLI fetches the account's visible model list and chooses its first model; `--model ID` selects another model. The bundled `--list-models` command does not list account-specific ChatGPT models.

A stable host ID and separate account registrations are stored in `~/.config/juliaforever/chatgpt`, or `JF_CHATGPT_DIR` if set. The directory and credential files use owner-only permissions on Unix; tokens are written atomically. Sign-out keeps the client and account identity for later reauthorization. Existing Codex and Pi OAuth credentials are not read or modified. Access tokens refresh as needed during a session, with refresh serialized across processes.

The provider sends streamed Responses requests with `store=false`, replays local history, and uses local function tools. It rejects unsupported request parameters and foreign tool namespaces. See [OpenAI's preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations). A rejected or incomplete stream cannot execute its tool calls. Histories can contain conversation and tool data.

Synthetic tests cover callback validation, signed ID tokens and key rotation, storage permissions, refresh and recovery, account selection, sign-out, streamed responses, and tool calls. **A real ChatGPT login, account-specific model request, and subscription eligibility have not been verified.** Windows storage is unsupported. The terminal selects the first visible model initially; the full-screen model picker fetches the current account-specific model list. Switching accounts requires restarting the CLI. The integration does not provide full Pi OAuth parity.
