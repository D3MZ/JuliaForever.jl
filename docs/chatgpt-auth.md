# ChatGPT plan sign-in design

ChatGPT plan sign-in is not implemented. Internal callback, code exchange, ID-token verification, protected storage, token refresh and plan-streaming components are covered by synthetic fixtures, but they are not connected to login or inference. [OpenAI documents a public-client flow](https://developers.openai.com/siwc/token-sharing-open-source) for open-source and locally hosted apps. Eligibility for this project has not been established; paid or remotely hosted apps have a separate interest process. An authorized plan access token is not an API key, and a subscription alone does not grant this project a credential.

The following work remains before accepting a login:

- The internal callback starts a loopback listener with fresh state, nonce and PKCE, validates the issued or saved client ID, and keeps the exact redirect URI. Returning sign-in can retain account hints, and explicit reconsent requests the plan scope. Authorization values and sensitive credential objects redact their ordinary and JSON representations; launcher failures return a redacted result. The internal Unix store persists a UUID host ID and isolated credentials with owner-only modes and atomic replacement. Test service compatibility before enabling the flow. See [registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).
- The internal verifier checks RS256 signatures with the fixed OpenAI JWKS, issuer, issued-client audience, expiry, nonce, subject and returning identity. It is used by the internal code exchange. Its keys and token cases are synthetic; no OpenAI-issued token has been tested. Use OpenID discovery as needed and verify service compatibility. OpenAI's [website guide](https://developers.openai.com/siwc/website) describes discovery and ID-token validation.
- The Unix store isolates validated account records and serializes refreshes across processes; an occupied lock returns busy, and the operating system releases it when the process exits. Terminal refresh errors clear tokens while retaining the account registration; transient and invalid-client errors leave the credentials intact. If a process dies after the server rotates a refresh token but before the replacement is persisted, the next invalid-grant response clears the stale tokens and the account must be reauthorized. Initial saves do not overwrite existing records; reauthorization uses compare-and-swap. Connect session selection and refresh to the provider, add sign-out and revocation, and test [accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions) against the service.
- Identity-only and nonrenewable grants are retained; inference still requires the direct-use scope and an unexpired access token. The internal plan adapter streams Responses with `store=false`, sends local functions as `additional_tools`, converts system messages to developer messages, and rejects unsupported parameters, expired sessions, missing scope and foreign tool namespaces. It is not exposed to the CLI and has not been tested against OpenAI. Complete session management and verify [preview field and tool restrictions](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations) and service behavior before enabling it.
- Test discovery, callback, token exchange, key rotation, signed and invalid ID tokens, refresh races, credential isolation, request restrictions and streaming failures with synthetic local fixtures. Test a real login and an eligible model request separately only when authorized; fixture tests alone do not establish service compatibility.
